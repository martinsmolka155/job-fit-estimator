# Job Fit & Salary Estimator

End-to-end pipeline that analyses a CV and returns:

- **Seniority score** (0–100) with weighted breakdown across experience, skills, progression, education, and domain expertise
- **Salary estimate** (CZK gross monthly range) backed by official ISPV M8r 2025 wage data
- **Three actionable recommendations** for ~30 % salary growth, generated by an LLM grounded in the parsed CV

CV is mapped to a CZ-ISCO-08 4-digit occupation code; the estimator looks up the matching ISPV decile distribution and applies regional, management, and inflation adjustments.

## Quick start

```bash
# 1. Install
make install
cp .env.example .env  # add OPENAI_API_KEY

# 2a. Streamlit UI (recommended for first run)
make run-ui                       # → http://localhost:8501
# In the sidebar, click "Stáhnout ISPV" to fetch data/ispv_2025.xlsx (~150 kB).

# 2b. Headless CLI
uv run python main.py path/to/cv.pdf --pretty

# 2c. HTTP API
uv run uvicorn api:app --reload   # → http://localhost:8000/docs
curl -F "cv=@path/to/cv.pdf" http://localhost:8000/analyze

# Docker
docker-compose up
```

PDF and DOCX are supported; scanned PDFs return a clean error (no OCR in MVP).

## Architecture

```
CV (PDF/DOCX)
    ↓
[1] Extractor   → ExtractedDocument (raw text + scanned-flag)
    ↓
[2] LLM Parser  → Resume (Pydantic, OpenAI Structured Outputs, temperature=0)
    ↓
[3] Validator   → list[ValidationFlag]   (substring hallucination guard)
    ↓
[4] Scorer      → SeniorityScore         (rule-based, 5 weighted components)
    ↓
[5] Estimator   → SalaryEstimate         (ISPV decile bands + multipliers)
    ↓
[6] LLM Explainer → Explanation          (3 recommendations, grounded in CV)
    ↓
PipelineResult (JSON-serialisable)
```

## Salary data: ISPV M8r

The estimator uses [ISPV M8r](https://www.ispv.cz/cz/vysledky-setreni/aktualni.aspx) — the official Czech Ministry of Labour wage statistics, published annually. The downloader scrapes the index page, fetches the M8r XLSX, and caches it locally.

For each CV the parser emits a 4-digit ISCO-08 code; the loader maps it to wage deciles and constructs five seniority bands:

| Band | Mapping (raw ISPV deciles) |
|---|---|
| junior | D1 → Q1 |
| medior | Q1 → MEDIAN → midpoint(MEDIAN, Q3) |
| senior | midpoint(MEDIAN, Q3) → Q3 → D9 |
| lead | D9 × [1.10, 1.20, 1.35] (extrapolated) |
| principal | D9 × [1.30, 1.50, 1.75] (extrapolated) |

Bands are then adjusted by:

- **Regional multiplier** — Praha ×1.15, Brno ×1.00, Ostrava/Olomouc/Zlín/Liberec ×0.85, smaller regions down to ×0.78. Non-CZ locations hard-fail.
- **Management multiplier** — ×1.10 when the parser detects an explicit lead/manager/director title or direct-reports count.
- **Inflation correction** — compounded per-month against the dataset publication date, using a per-occupation-family annual rate from `data/inflation_factors.json`.

If the parser emits an ISCO code absent from ISPV (model hallucination), the loader falls back to the highest-POCET code in the same `occupation_family`.

## Key design decisions

**Rule-based scoring over ML.** Every score has a human-readable reasoning string. ML would need labelled training data we don't have, and a black-box model would make it impossible to justify *why* a candidate scored 67 vs 68. Transparency over accuracy.

**Hallucination guard at parse time.** `ResumeValidator` cross-checks every extracted field (companies, emails, skills, schools) against the raw CV text using `_normalize()` (lowercase + strip diacritics + collapse whitespace). Catches the bulk of fabrications at near-zero cost.

**OpenAI Structured Outputs, no LangChain.** `client.beta.chat.completions.parse` with Pydantic v2 gives deterministic structured extraction in ~150 lines, with explicit retry, refusal handling, and cost tracking. LangChain would add weight without buying anything for this surface area.

**Temperature 0.0.** Structured extraction is deterministic — same CV in, same JSON out. Default `1.0` would make eval results flaky.

**Hard fail over silent fallback.** Non-CZ location, missing ISPV data, or empty result raises `ISPVLookupError` — surfaced in the UI as a clean warning. Returning a number we can't defend would mislead the user.

## Honest limits

Each one is a tradeoff, not a bug. They are visible to anyone reading the source.

| Area | Current | Production-grade |
|---|---|---|
| Salary data lag | ISPV publishes Q1 of the following year (2025 data → March 2026 release). Inflation correction compounds per-month from publication. | Continuous refresh + half-year revision import; supplementary regional XLSX import for sub-national breakdowns |
| ISCO accuracy | LLM-emitted 4-digit code, validated against the loaded ISPV whitelist with family-level fallback for unknown codes | Whitelist enforcement at parse time + secondary classifier (taxonomy lookup against CZ-ISCO official list) |
| Sector tier | Not modeled — banking/FAANG/agency/government can shift estimates by ±15 % | Curated company-tier dictionary + parser-detected `Experience.company_tier` field |
| HPP vs IČO | All output is HPP gross monthly. UI badge documents the distinction; no IČO equivalent computed | Dual output (HPP + IČO equivalent ~×1.4–1.6) with toggle |
| Lead/principal bands | Extrapolated above ISPV's 90th percentile using documented multipliers | Custom survey of senior compensation + equity disclosure |
| Tech bonus underreport | ISPV captures payroll only; AI/ML/cloud premiums and equity are partly invisible. Mitigated by per-family inflation rates (IT ×1.08/yr) | Vendor-specific compensation feeds (e.g. AON, Mercer) |
| Sample suppression | Some narrow ISCO codes have insufficient ISPV respondents; loader falls back to broader codes with `confidence=medium` warning | Multi-source merge to fill gaps, region-stratified sampling |
| Multi-language | English + Czech via LLM prompt | Full localisation layer with locale detection |
| OCR | Not supported — scanned PDFs return a clean error | Tesseract + post-processing |
| Eval dataset | 4 fixtures (IT dev, healthcare nurse, services cook, sales rep) + 1 real-world CV | 100+ anonymised real CVs with ground-truth labels |

See `docs/PRODUCTION_ROADMAP.md` for a sequenced plan of what one to two weeks vs one to two months of further work would unlock.

## Project layout

```
src/
├── schemas.py       # Pydantic v2 models — single source of truth
├── extractor.py     # PDF/DOCX → raw text
├── parser.py        # Raw text → Resume (LLM)
├── validator.py     # Hallucination guard
├── scorer.py        # Rule-based seniority score
├── salary_ispv.py   # ISPV M8r loader + decile mapping + fallback chain
├── estimator.py     # Seniority + ISPV → SalaryEstimate
├── explainer.py     # LLM recommendations
├── pipeline.py      # End-to-end orchestrator
└── llm_provider.py  # OpenAI provider via abstract base class

prompts/             # System prompts (parser, explainer)
data/                # ISPV XLSX (downloaded), inflation factors
ui/                  # Streamlit app
tests/               # 182 pytest tests + 4 golden-set evals (live LLM)
scripts/             # Eval harness + fixture generator
main.py              # CLI entrypoint
api.py               # FastAPI endpoint
```

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `OPENAI_API_KEY` | required | OpenAI API key |
| `PARSER_MODEL` | `gpt-4o-mini` | Model for CV parsing |
| `EXPLAINER_MODEL` | `gpt-4o-mini` | Model for recommendations |
| `DAILY_API_BUDGET_USD` | `5.00` | Hard cap; pipeline raises before exceeding |

Per-CV cost is approximately $0.001–$0.002 with `gpt-4o-mini`, $0.02–$0.04 with `gpt-4o`. End-to-end latency 3–6 s.
